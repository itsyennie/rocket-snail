# 자동 복구 및 원인 기록 보강 — 0.2.9

2026-11-02 수정. 배포 ZIP 검증 결과는 RELEASE_VALIDATION_0.2.9.md를 참고하세요.

- 감시를 계정/창 초기화 이전부터 시작합니다. JavaScript 치명적 오류나 처리되지 않은 Promise 거절은 안전한 오류 정보만 기록하고 종료해 감시자가 재실행하게 합니다.
- 10분에 3번 실패하면 영구 중단하지 않고, 허용 시간이 지난 뒤 재시도합니다. 실행 자체가 실패한 경우는 30초 간격으로 재시도합니다.
- 앱이 살아 있는 동안 감시자만 종료되면 5초 후 새 감시자를 만듭니다.
- 화면 프로세스 복구가 평생 3회로 제한되던 로직도 반복 오류 시 대기 후 재시도하도록 변경했습니다.
- 직접 종료와 Windows 세션 종료는 재실행 대상에서 제외합니다.
- 프로세스 ID, 실행 단계, 가동 시간, 종료 코드, 오류가 난 앱 소스 파일/줄/열을 기록합니다. 원문 오류 메시지·전체 스택·계정·토큰·채팅은 진단에 포함하지 않습니다.
- 연결·캐릭터 화면과 트레이의 '진단 기록 열기'는 최근 최대 400개 이벤트를 시간순으로 정리합니다. 보고서는 PC에서만 만들고 외부로 전송하지 않습니다.

## 검증

단위·통합 테스트 52개 통과. 별도 Windows 패키지의 격리 프로필에서 UI·진단 보고서 생성, 치명적 JavaScript 오류 기록 후 복구, 강제 종료 복구, 감시자 강제 종료 후 교체를 검증했습니다. 각 복구 뒤 픽셀 캐릭터가 표시되고 정상 종료 시 감시를 해제하는 것을 확인했습니다.

## 한계

오류 정보가 없는 강제 종료, 운영체제 종료, 외부 프로그램의 종료 명령은 앱 로그만으로 원인을 확정할 수 없습니다. 프로세스가 살아 있는 채 멈춘 상태는 기록만 하며 자동 강제 종료하지 않습니다. 앱과 감시자를 함께 종료하거나 운영체제가 실행을 차단하면 복구를 보장할 수 없습니다. 실제 재부팅·로그오프와 장시간 안정성은 이번 검증에 포함하지 않았습니다.
